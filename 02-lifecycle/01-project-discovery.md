# Phase 01: Project Discovery

---

## 1. Phase Overview
Project Discovery is the initial exploratory stage where a software idea or business opportunity is conceptualized, framed, and evaluated for strategic alignment. It establishes the "North Star" vision before any technical investment is made.

---

## 2. Inputs
*   Initial project idea, user inspiration, or business hypothesis.
*   Stakeholder vision or personal learning goals.
*   Market context, competitor landscape, or existing alternative solutions.

---

## 3. Activities
1.  **Stakeholder Interview & Vision Framing**: Articulate what the software should do and who will use it.
2.  **Target User Profiling**: Define primary and secondary user personas, their goals, technical literacy, and environments.
3.  **Value Proposition Canvas**: Document why this solution is better, faster, or simpler than existing manual workflows or rival products.
4.  **Scope Boundaries (In-Scope vs. Out-of-Scope)**: Establish high-level boundaries to prevent scope creep from day one.
5.  **Success Metrics Definition**: Establish quantitative metrics (e.g. daily active users, offline sync latency $< 1$s, app crash rate $< 0.1\%$).

---

## 4. Expected Outputs
*   Clear understanding of user personas and core value proposition.
*   Documented list of high-level goals and explicitly excluded capabilities.
*   Preliminary technical direction (e.g., native Android vs. web application).

---

## 5. Deliverables
*   `01-project-proposal.md` (using the template from `07-templates/01-project-proposal.md`).
*   High-level User Persona Briefs.

---

## 6. Completion Criteria (Exit Gate)

- [ ] Is the primary user problem clearly defined in a single sentence?
- [ ] Are target user personas documented with concrete pain points?
- [ ] Are explicit out-of-scope boundaries defined for the initial version (v1.0)?
- [ ] Has the Project Proposal document been drafted and reviewed?
- [ ] Is there stakeholder or developer sign-off to proceed to Problem Analysis?
